### Add a compatibility notice

For the major and minor releases, add a compatibility notice for the version
under development, in the
**Compatibility notices** section of the **Getting Started** page
(for example `v6.0 (not yet released)`), and update it with each issue and
each commit that breaks the compatibility of existing code, changes its
behaviour, deprecates a definition, or adds a new feature:

- group the entries by kind: new features, deprecated definitions, changes
  that break the compilation, and changes of behaviour;
- for each entry, give the old and the new names, and what the applications
  must change;
- do not postpone the entries to the release, because the details are soon
  forgotten.

The patch releases do not need a compatibility notice.
